# AIエージェント連携

AIエージェントはこのアプリの「ユーザー」として、エージェントごとに識別されます。接続方法はMCP(OAuth)とREST API(トークン)の2つです。

## エージェントの権限

| 項目       | 意味                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| 読み取り   | ノートを読めるか                                                                           |
| 書き込み   | `none`(読み取りのみ)/ `propose`(提案のみ)/ `direct`(直接書き込み可)                        |
| フォルダ   | 触れるフォルダ。空ならすべて                                                               |
| 自動マージ | 競合なくマージできる提案を自動で取り込む(メモ整理などの軽い作業向け)。対象フォルダも絞れる |
| 実行場所   | `external`(外部サービスのAI)/ `local`(このサーバーと同じ管理下のAI)                        |

- `external` のエージェントには、AIポリシーで「外部AI可」のノートしか見えません。さらに機密検出に引っかかった値は `[SECRET_1a2b3c4d5e6f7a8b]` のようなランダムな置換文字列で渡されます(`block` モードではそのノートを読めません)。エージェントが置換文字列を含む文章を書き戻すと、サーバー側で元の値に戻ります。一度伏せた値は、どの文脈に現れても以後エージェントには伏せて渡します。
- エージェントは、読めない場所(フォルダ制限の外、AIポリシーが許さないフォルダ)には書き込めません。段落ごとの作成者(blame)はエージェントには返さず、添付ファイルは画像とPDFだけを返します(ノートは伏せ字付きの `/api/note` で読みます)。
- 直接書き込み可のエージェントでも、**人間がそのノートを編集中**か、**エージェントが読んだ後にノートが変わっていた**(`base_sha` の不一致)場合は自動的に提案に切り替わります。

## MCPで接続する

MCPサーバーのURLは `https://<ドメイン>/mcp`(Streamable HTTP)です。

1. MCPクライアントにURLを追加する。
2. クライアントが動的クライアント登録とOAuth認可を自動で行い、ブラウザで認可画面が開く。
3. パスキーでログインし、エージェント名・フォルダ・書き込み方法・スコープを選んで許可する。

認可はOAuth 2.1(認可コード + PKCE S256、リフレッシュトークンはローテーション)です。許可したクライアントは設定画面の「エージェント」で確認・失効できます。

### 提供するツール

| ツール                               | 内容                                            |
| ------------------------------------ | ----------------------------------------------- |
| `search_notes`                       | 全文+ベクトルのハイブリッド検索                 |
| `list_notes`                         | ノート一覧(フォルダ指定可)                      |
| `read_note`                          | 本文と `sha` / `commit` を返す                  |
| `get_backlinks`                      | バックリンク                                    |
| `query_view`                         | DBビューを実行                                  |
| `propose_changes`                    | 複数ファイルの変更を1つの提案として送る         |
| `write_note`                         | 1ファイルを書く(直接書き込みできない場合は提案) |
| `list_my_proposals` / `get_proposal` | 自分の提案の状態                                |

## REST APIで接続する

設定画面の「エージェント」でエージェントを作り、トークンを発行します(トークンは発行時に一度だけ表示され、サーバーにはハッシュのみ保存されます)。

```sh
TOKEN=gmp_xxx
curl -H "Authorization: Bearer $TOKEN" "https://notes.example.com/api/search?q=会議"
curl -H "Authorization: Bearer $TOKEN" "https://notes.example.com/api/note?path=Projects/Plan.md"

curl -X POST -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  https://notes.example.com/api/changes -d '{
    "title": "議事録を整理",
    "changes": [{ "path": "Meetings/2026-10-10.md", "content": "# 定例\n\n- 決定事項 ...\n" }],
    "baseShas": { "Meetings/2026-10-10.md": "<read_noteで得たsha>" }
  }'
```

### スコープ

| スコープ        | 許可すること                                                                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `notes:read`    | 読み取り・検索                                                                                                                                                                             |
| `notes:propose` | 提案の作成                                                                                                                                                                                 |
| `notes:write`   | 直接書き込み(エージェントの書き込み設定が `direct` の場合のみ有効)                                                                                                                         |
| `notes:capture` | クイックメモの追加だけ。**あなた自身の端末用**で、作成者は人間として記録される。個人用トークンでのみ発行でき、OAuth(MCPクライアント)には発行しない。エージェントのフォルダ制限は適用される |

## 提案と承認

- 提案は `proposals/<id>` ブランチとして保存されます(GitHub保存では `gmemo/proposals/<id>`)。承認するとマージコミットとしてmainに入り、作成者(author)はエージェント名になります。
- 承認画面では段落ごとの差分が出ます。mainが提案後に変わっていても、別の段落・別のフロントマターキーなら自動でマージされ、**同じ段落を両方が変えたときだけ**選択が必要です(上:いまの内容/下:提案)。
- 却下した提案は `rejected/<id>` として残ります。

## AIの変更を取り消す

履歴画面で、コミット単位の取り消しと「このエージェントの変更をすべて取り消す」ができます。取り消しも三方向マージで行うため、その後にあなたが書いた内容は残ります。衝突する場合は取り消しが提案として承認画面に出ます。

## 作成者の記録

- ファイル単位:新規作成時にフロントマターへ `created_by: human | ai` と `ai_agent: <エージェント名>` を記録
- 変更単位:Gitのauthor(エージェント名 / `<agentId>@agents.gmemo.local`)とコミットメッセージのトレーラー(`Gmemo-Author-Kind`, `Gmemo-Agent`, `Gmemo-Proposal`)
- 画面では、AIが最後に書いた段落を色分けして表示します(段落単位のblame)

## iOSのショートカットから投げ込む

1. 設定 → エージェントで「iPhoneショートカット」などのエージェントを作り、スコープ `notes:capture` だけのトークンを発行する。
2. ショートカットアプリで「URLの内容を取得」アクションを作る。
   - URL:`https://<ドメイン>/api/capture`
   - 方法:POST、ヘッダ `Authorization: Bearer <トークン>`
   - 本文(JSON):`text` に「ショートカットの入力」、必要なら `title`、`folder`
3. 共有シートに表示する設定をオンにする。

`title` なしだと `Inbox/<日付>.md` に時刻付きで追記、ありだと新しいノートを作ります。AndroidやデスクトップのChromeでは、PWAをインストールすると共有シートに直接表示されます。
