# セキュリティ

## 前提

- 1つのサーバーを複数の人が使う。アカウント同士は完全に分かれていて、ほかの人のノート・エージェント・トークンには一切触れられない(すべての表とクエリが `user_id` で絞られ、テストで確認している)。
- サーバーの運用者(Cloudflare アカウントやサーバーの管理者)は、技術的には保存されたデータを読める。このサービス内に保存したノートは暗号化していない(下の「E2EEを採用しない理由」)。運用者を信頼できない場合は、GitHub 保存を選ぶか、自分で運用する。
- 最初のアカウントが管理者。管理者はアカウントの削除と、リカバリーコードの再発行ができる(ノートを読む機能はない)。

## 認証

- **人間はパスキーのみ。** パスワードを持たないので、漏洩してもリスト型攻撃やフィッシングの材料になりません。サーバーが持つのは公開鍵と署名カウンタだけです。
- 最初の(管理者)アカウントの作成には、セットアップトークン(`GMEMO_SETUP_TOKEN`、またはNode.jsの起動時に表示される24時間有効のトークン)が必要です。公開直後に第三者が管理者になることはできません。
- 2人目以降は `GMEMO_SIGNUP` に従います。既定の `invite` では、管理者が発行した1回限り・期限付きの招待コード(ハッシュで保存)が必要です。
- リカバリーコード10個をアカウント作成時に発行し、SHA-256ハッシュで保存します(各コード1回限り)。ログインにはユーザー名とコードの組が必要です。リカバリーコードでのログインは1日だけ有効で、新しいパスキーの登録を促します。
- パスキー登録・ログインのチャレンジはデータベースに保存し、1回だけ使えます(複数のインスタンスで動くため)。
- セッションはランダムな256ビットトークンをHttpOnly / SameSite=Lax クッキーに入れ、サーバーにはハッシュのみ保存します。クッキー認証の書き込み系リクエストは `Origin` を検証します。

## エージェントとトークン

- エージェントはOAuth 2.1(PKCE S256必須、公開クライアントのみ、リフレッシュトークンはローテーション)または個人用トークンで接続します。
- トークンはすべてスコープ付き・期限付き・失効可能で、SHA-256ハッシュのみ保存します。エージェントを失効すると全トークンが即座に無効になります。
- 実際にできることは「トークンのスコープ」と「エージェントの設定(読み取り、書き込み方法、フォルダ)」の積です。
- `.gmemo/`(ワークスペース設定)はエージェントから書き換えられません。
- OAuthクライアント(MCPクライアント)の登録はサーバー全体で共通ですが、どのエージェントとしてつながるかはユーザーごとに同意画面で決まり、発行されるトークンはそのユーザーにだけ有効です。

## GitHub 保存

- GitHubのトークンは、サーバーのシークレット(`GMEMO_SECRET_KEY`)から作った鍵で AES-256-GCM で暗号化して保存し、画面やAPIで再表示しません。
- 必要な権限は、対象リポジトリだけの「Contents: Read and write」です(Fine-grained token)。
- APIに渡すブランチ名・コミットIDは形式を検証してからURLに入れます。
- サーバーがGitHubに強制pushすることはありません(fast-forwardのみ)。

## データが外に出る経路

外部LLMへの送信は、すべて1か所(`AiGateway` / `AgentLens`)を通ります。もう一つの経路は利用者が自分で作るカレンダーの公開URLで、予定のタイトルと日時だけを、同じAIポリシー(「外部AI可」のノートのみ)と機密検出に従って出します([カレンダー連携](calendar.md))。

1. フォルダ単位・ノート単位のAIポリシー(ユーザーごと)で、送ってよいノートだけに絞る
2. ローカルで機密検出し、警告・マスキング・ブロックのいずれかを適用
3. マスキングした値は返答を受け取った後にローカルで戻す
4. 送信の事実(目的、送信先、対象ノートのパス、検出件数)を監査ログに残す

## E2EEを採用しない理由

- E2EEにすると、サーバー側で全文検索・埋め込み・AIによる整理、そしてAIエージェントによる編集ができなくなる
- 代わりに、データが外に出る経路である外部LLM送信を制御する
- 運用者を信頼できない場合は、自分で運用する(Cloudflare の無料枠でも動く)か、GitHub 保存を選ぶ

Cloudflare D1 のデータは Cloudflare によって保存時に暗号化されます。セルフホストの場合はOSのディスク暗号化を推奨します。

## 情報最小化

- アカウント情報はユーザー名とパスキー公開鍵のみ
- メールアドレス、本名、IPアドレスは保存しない(アプリはIPを記録しません)
- アカウントを削除すると、このサービス内のノート・履歴・インデックス・エージェント・トークンをすべて削除します

## Webアプリ

- 厳しめのCSP(`script-src 'self'`、外部リソースなし)、`X-Frame-Options: DENY`、`nosniff`
- Markdownの描画はサニタイズ済みHTMLのみ
- 添付ファイルは `nosniff` と制限的なCSP付きで配信
- 取り込むカレンダーのURLは、サーバーが取得するため、社内・ループバック・リンクローカルのアドレスを拒否します(`GMEMO_INSECURE_DEV=1` の場合を除く)

## 脆弱性の報告

公開のIssueではなく、リポジトリのSecurity Advisories(非公開の報告)からお知らせください。
