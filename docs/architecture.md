# アーキテクチャ

## データ設計

正のデータはGitリポジトリ内のMarkdownファイルです。それ以外はすべてファイルから再生成できる派生データか、認証などの管理情報です。

| 層 | 実装 | 役割 |
| --- | --- | --- |
| ノート | `notes/**/*.md`(Markdown + YAMLフロントマター) | 正のデータ。Obsidianでそのまま開ける |
| 履歴 | `notes/.git` | 変更履歴、作成者、提案ブランチ、マージ |
| ビュー定義・AIポリシー | `notes/.views/*.yaml`、`notes/.gmemo/policy.yaml` | ファイルとして保存し、履歴も残る |
| インデックス | `index.db`(SQLite) | 全文検索(FTS5 trigram:日本語対応)、埋め込みベクトル、リンクグラフ、タグ、プロパティ |
| 管理情報 | `app.db`(SQLite) | パスキー公開鍵、OAuthクライアント、トークン(ハッシュ)、エージェント、提案のメタデータ、監査ログ |

`index.db` は最後にインデックスしたコミットを記録し、起動時やコミットのたびに差分だけを更新します。壊れたり消えたりしても `gmemo reindex`(または起動時の自動検出)でリポジトリから作り直せます。

スキーマ変更は `PRAGMA user_version` で管理するマイグレーションで、起動時に自動適用されます。

## Gitの使い方

- 作業ツリーは常に `main` を反映します(Obsidianで開くため)。
- サーバーからの書き込みは一時インデックス(`GIT_INDEX_FILE`)と `commit-tree` / `update-ref`(compare-and-swap)で行い、`main` の場合だけ作業ツリーの該当ファイルを更新します。他のブランチの書き込みは作業ツリーに触れません。
- リポジトリへの書き込みはプロセス内のミューテックスで直列化します。書き込みの前には必ず「アプリ外の編集」を人間のコミットとして取り込みます。
- 提案は `proposals/<id>` ブランチ。承認はマージコミット(親:main、提案ブランチ)で、authorはエージェント。
- 作成者は Git の author で区別します:人間は `human@gmemo.local`、エージェントは `<agentId>@agents.gmemo.local`。

## マージモデル

すべての競合を三方向マージで扱います。書き込み元は3種類、判定は1つです。

```
 AIエージェント ─┐
 オフラインの端末 ─┼─▶ base(読んだ時点)と main の差分を三方向マージ ─┬─ 自動マージ → main
 人間(別タブ等) ─┘                                                  └─ 競合 → 提案(承認画面)
```

- **フロントマター**:キー単位。片方だけが変えたキーはそのまま採用。タグのようなスカラー配列は集合としてマージ(両方の追加を残し、どちらかの削除を反映)。両方が別の値にした場合だけ競合。
- **本文**:段落(ブロック)単位。見出し、段落、リストの各項目、コードブロック、引用、表をそれぞれ1ブロックとし、ブロック列に対してLCSベースのdiff3を行う。**隣り合う段落**への同時編集は競合にしない。
- 同じ仕組みを、Gitのマージドライバー(`.gitattributes` で `*.md merge=gmemo`)としても登録しているので、`notes/` で手動で `git merge` してもフロントマターが壊れにくい。

保存時は、クライアントが編集を始めた時点のblob(`baseSha`)を送ります。サーバーはmainの現在のblobと比べ、違っていれば三方向マージします。

## 段落単位の作成者表示(blame)

ファイルの `main` 上の履歴(first-parent)を古い順にたどり、各バージョンのブロック列を前のバージョンとdiffします。変わらなかったブロックは前の作成者を引き継ぎ、新しく現れた・変わったブロックはそのコミットのauthorになります。

## 検索

- 全文検索:SQLite FTS5(trigramトークナイザ)。2文字以下の検索はLIKEにフォールバック。
- ベクトル検索:ノートを段落単位で約900文字のチャンクにまとめて埋め込み。ローカル埋め込みモデル(Ollama等)か、内蔵の文字n-gramハッシュベクトル。
- ハイブリッド:Reciprocal Rank Fusion。
- 「ノートに質問」:ハイブリッド検索で関連チャンクを集め、AIゲートウェイ経由でLLMに渡す。

## パッケージ

- `packages/core`:DOMにもNodeにも依存しない純粋ロジック。サーバーとWebの両方で使う。
- `packages/server`:Hono(HTTP)、better-sqlite3、git CLI、@simplewebauthn/server、MCP TypeScript SDK。
- `packages/web`:React + Vite + CodeMirror 6 のPWA。
