# ノートの保存先

ユーザーごとに、ノートと変更履歴をどこに置くかを選べます(**設定 → 保存先**)。どちらを選んでも、アプリの機能(AIの提案と承認、段落単位のマージ、誰が書いたかの表示、履歴と取り消し)は同じです。

|                  | このサービス内(既定)                          | 自分の GitHub リポジトリ                                            |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------------- |
| 置き場所         | サーバーのデータベース(Cloudflare なら D1)    | あなたの GitHub リポジトリ(非公開リポジトリ推奨)                    |
| 形式             | Gitと同じオブジェクト(コミット・ツリー・blob) | 本物のGitコミット                                                   |
| 他のツールから   | エクスポート(.tar.gz)で取り出す               | `git clone` / GitHub の画面 / Obsidian Git などで直接読み書きできる |
| アプリ外での編集 | —                                             | push された変更は数十秒以内に取り込まれる                           |
| 1ファイルの上限  | 約1.9MB(R2 を有効にした場合、添付は50MB)      | 20MB(アップロード時)                                                |
| 必要なもの       | なし                                          | Fine-grained personal access token                                  |
| 向いている人     | すぐ使いたい、GitHubを使っていない            | ノートを自分の管理下に置きたい、既存のMarkdownリポジトリを使いたい  |

## このサービス内に保存する

アカウントを作った時点でこちらになっています。ノートは Git と同じ形式(同じハッシュ値)で、ユーザーごとに分けてデータベースに保存されます。履歴も全部残ります。

取り出すときは **設定 → データ・アカウント → エクスポート** で、全ノートを .tar.gz でダウンロードできます(最新の状態のみ。履歴は含みません)。

## GitHub に保存する

### 1. リポジトリを用意する

GitHub で新しいリポジトリを作ります。**非公開(Private)** にしてください。空のままで構いません(最初のコミットはアプリが作ります)。すでにMarkdownのノートが入っているリポジトリも使えます。

### 2. トークンを作る

[Fine-grained personal access token](https://github.com/settings/personal-access-tokens/new) を作ります。

- **Repository access**: Only select repositories → 1 で用意したリポジトリだけを選ぶ
- **Permissions → Repository permissions → Contents**: **Read and write**
- それ以外の権限は不要です
- 有効期限は自由です。期限が切れたら、同じ画面で新しいトークンを入れ直してください

### 3. アプリで接続する

**設定 → 保存先 → 自分のGitHub** で、オーナー(ユーザー名または組織名)、リポジトリ名、ブランチ(既定 `main`)、トークンを入れて **接続して切り替える** を押します。

- 「今のノートをこのリポジトリにコピーする」にチェックすると、いまのノート(最新の状態)が1つのコミットとしてリポジトリに入ります。同じ名前のファイルは上書きされます。**これまでの履歴はコピーされません**(元の場所に残ります)。
- 切り替えると、未処理の提案は閉じられます(提案のブランチは保存先をまたいで移せないため)。
- トークンはサーバーで暗号化して保存され、画面やAPIで再表示されることはありません。

### GitHub 上での見え方

- ノートの変更は、そのままコミットになります。作成者(author)は、人間なら `<ユーザー名> <human@gmemo.local>`、AIエージェントなら `<エージェント名> <agentId@agents.gmemo.local>` です。コミッターは `gmemo` です。
- AIの提案は `gmemo/proposals/<id>` というブランチとして作られ、承認するとマージコミットとして `main` に入ります。却下した提案は `gmemo/rejected/<id>` に残ります。
- AIポリシーは `.gmemo/policy.yaml`、データベースビューは `.views/*.yaml` としてリポジトリに入ります。

### アプリ外での編集

PCで `git push` した変更や、GitHub の画面での編集は、アプリが次にリポジトリを確認したとき(既定で最大30秒後)に取り込まれ、検索などに反映されます。**設定 → データ・アカウント → 今すぐ同期** ですぐに取り込めます。

アプリでの保存とアプリ外の push が同時に起きた場合、アプリ側は最新の `main` の上で書き直してからコミットします(強制pushはしません)。

### 注意

- GitHub API には回数制限(トークンごとに1時間5000回)があります。通常の使い方では届きませんが、大量のノートを一度に操作すると一時的に失敗することがあります。
- GitHub に置いたノートは、AIポリシーとは関係なく GitHub(Microsoft)のサーバーに保存されます。機密性の高いノートを GitHub に置きたくない場合は、このサービス内の保存を選んでください。

## 元に戻す

**設定 → 保存先 → このサービス内に戻す** で、GitHub のいまのノートをこのサービス内にコピーして切り替えます。以前このサービス内に保存していた場合は、その履歴の続きとして入ります。不要になったら **保存したGitHub接続を削除** でトークンを消せます。
